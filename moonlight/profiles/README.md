# profiles/ - calibration + config profiles

Per-bot configuration. Each `<name>.json` stores calibrated screen regions
keyed to a stable UI **landmark** (not absolute coordinates), so the profile
survives moving/resizing the client window. Generated by `calibrate.py`;
loaded by the bot at startup (region rects) and by `ui.py` (`ProfileSelector`).

## Status

- ⚠️ **No profiles yet** — the first is created when a user runs calibration:
  `python calibrate.py` (see `calibrate.py` docstring / `--help`).
- The serial port and behavior config planned for T16 (ArduinoInput) will be
  added to the schema then — `calibrate.py` currently writes only
  `landmark` + `regions`.

## JSON schema (written by `calibrate.py`)

```json
{
  "landmark": [x, y],
  "regions": {
    "hp_bar":          [x, y, w, h],
    "mp_bar":          [x, y, w, h],
    "battle_list":     [x, y, w, h],
    "minimap":         [x, y, w, h],
    "floor_indicator": [x, y, w, h],
    "status_icons":    [x, y, w, h],
    "game_grid":       [x, y, w, h]
  }
}
```

- `landmark` — absolute `[x, y]` of the stable UI element recorded at
  calibration time; the runtime re-locates it by template match.
- `regions.*` — `[x, y, w, h]` **relative to the landmark**; the bot computes
  `landmark_abs + region_relative` at runtime.
- Canonical region keys (see `calibrate.REGIONS`): `hp_bar`, `mp_bar`,
  `battle_list`, `minimap`, `floor_indicator`, `status_icons`, `game_grid`.

## Conventions

- Do NOT commit machine-specific paths or real serial ports; provide a
  `.example.json` template instead.
