# C4.F1.K1: Check the layout at Start

Part of [gui-calibration](../../prs/gui-calibration.md).

## Brief

Before the loop starts, check the client size equals `window_size`, and that the Stop button is still at the landmark. If not, raise `ValueError("Layout changed, recalibrate")` from `build_gui_loop`; `gui/app.py` already logs it. Profiles without `window_size` skip the size check. Without `stop_button.png` the Stop button check is skipped and a log line says so.

**Don't touch:** gui/app.py.

**Done when:** `pytest tests/unit/test_loop_factory.py` passes; a fake window with a different size gets the error; a matching one starts; no Stop button image logs the skip.

## Router notes

2026-10-22:
- The check runs before the Arduino opens, so a stale layout never moves the mouse.
- The Stop button may sit up to 2 px off the landmark. A profile with landmark (0, 0) was never measured, so its Stop check is skipped.

## What changed and why

- New `autofind.find_stop_button(screenshot, scale)` matches `stop_button.png`, resized by `ui_scale`, and returns its top-left or None.
- New `check_layout` in `loop_factory.py` grabs one frame. A size other than `window_size`, or a Stop button missing or moved from the landmark, raises `ValueError("Layout changed, recalibrate")`.
- No `window_size` skips the size check. No `stop_button.png` skips the Stop check and logs a line. The log goes to the GUI feed, or the module logger when there is none.
- `build_gui_loop` creates the capture first, runs the check, and only then opens the backend.
- Tests: a different size raises, the same size starts and logs the skip, the Stop button at the landmark starts and 100 px off raises. The tests point the anchors at a tmp dir and clear the cached anchors, so the owner's local images never leak in.
