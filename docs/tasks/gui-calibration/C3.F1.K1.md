# C3.F1.K1: Measure the UI scale

Part of [gui-calibration](../../prs/gui-calibration.md).

## Brief

`ui_scale` = found Stop button width ÷ `stop_button.png` width, rounded to 0.05. The found Stop button is also the landmark. Without `stop_button.png`, `ui_scale` is 1.0 and the landmark is `(0, 0)`. The Calibration tab pre-fills its UI scale number with it.

**Don't touch:** the readers.

**Done when:** a golden screenshot gives `ui_scale` 1.0, and the same screenshot enlarged 1.5× with `cv2.resize` gives 1.5.

## Router notes

2026-10-22:
- The readers use each region as an absolute box and never add the landmark, so the regions stay absolute. Only the profile's `landmark` field changes.

## What changed and why

- New `find_ui_scale(screenshot)` in `moonlight/setup/autofind.py` returns `(ui_scale, landmark)`.
- It matches `stop_button.png` resized to every scale from 0.5 to 3.0 in 0.05 steps, nearest to 1.0 first, and stops at a score of 0.99. The scale that matched is the UI scale, so it is already a multiple of 0.05.
- On a golden frame it gives 1.0 at (2510, 263) in 0.05 s. Enlarged 1.5x it gives 1.5 in about 5.5 s, which is fine for a one-off calibration.
- No `stop_button.png` or no match gives 1.0 and (0, 0).
- The Calibration tab passes the landmark to `CalibrationSteps` and pre-fills the UI scale with the measured value. When the Stop button isn't found it keeps the old profile's scale, so a failed search doesn't reset it to 1.0.
