# C2.F4.K5: Named calibrations

Part of [gui-calibration](../../prs/gui-calibration.md).

## Brief

Today the tab always overwrites the profile named in the bot config (`moonlight_user`), and nothing in the GUI shows or changes which one the bot uses.
  - The Calibration tab shows a dropdown of saved calibrations (one per file in the profiles folder). Picking one sets the config's `profile` field, so the bot uses it on its next start.
  - The review has Save (writes the picked calibration) and Save as (asks for a name, then saves under it and picks it). An existing name asks before overwriting.
  - Esc's partial save writes the picked calibration.

**Done when:** pytest passes, with tests for name checks and listing (tmp_path only). Owner checks: save as a new name, switch between two calibrations, start the bot and see it use the picked one.

## Router notes

2026-10-22:
- Where the name lives:
  - The bot reads `BotConfig.profile` from the picked named config (`loop_factory.picked_config()` and `load_real_config()`).
  - To change it, load the picked config, set `profile` with `dataclasses.replace`, and `cfg.save(picked_config())`. This is the same path `Tab.apply` uses.
  - Settings' Save only writes its own options, so it keeps `profile`.
- The dropdown:
  - A `CTkOptionMenu` in the idle view, filled from `ProfileManager(cfg.profiles_dir).list_profiles()` and showing `cfg.profile`.
  - Picking a name writes it at once and logs `calibration: bot uses <name> (from next start)`. This is allowed while the bot runs.
  - Refill it after every save and in a listener added to `ctx.config_listeners`, so picking another named config updates it.
  - If `cfg.profile` has no file yet, show it anyway.
- Names:
  - Add `ProfileManager.valid_name(name) -> bool`: 1 to 40 characters, letters, digits, `_` and `-` only. This blocks paths and dots.
  - Test it, plus `list_profiles` with tmp_path.
- Saving:
  - Save as uses `ctk.CTkInputDialog`.
  - An invalid name logs an error and saves nothing.
  - An existing name asks with `messagebox.askyesno` before it overwrites.
  - After Save as, the new name becomes the picked one: write it to the config and select it in the dropdown.
  - Save and Esc's partial save write to the picked name.
  - The old profile used to fill in missing boxes is the picked one too.

## What changed and why

- The Calibration tab has a dropdown of saved calibrations. Picking one writes it to the picked config's `profile`, so the bot uses it from its next start. It refills after every save and when another named config is picked.
- The review has Save and Save as. Save as asks for a name, refuses a bad one, asks before overwriting, then saves and picks it.
- Save, Esc's partial save and the old profile that fills missing boxes all use the picked calibration.
- `ProfileManager.valid_name` allows 1 to 40 letters, digits, `_` and `-`, so a name can't be a path. Only ASCII letters, like config names.
- Save as checks the UI scale before asking for a name, so a bad scale doesn't waste the dialog.
- Rule P1 ("One calibration") in the PR doc now conflicts with this task. The owner asked for named calibrations; the PR doc is not in `writes`, so P1 is left for the router to update.
