# C3.F3.K1: Minimap uses the scale

Part of [gui-calibration](../../prs/gui-calibration.md).

## Brief

Scale `RADAR_WIDTH/HEIGHT` and `PLAYER_CENTER_X/Y`; pixels per tile = `ui_scale`. Don't change the constants' values.

**Done when:** `pytest tests/unit/test_minimap.py` passes; the same 1.5× check as C3.F2.K1, for position and movement.

## Router notes

2026-10-22:
- `RADAR_WIDTH/HEIGHT` and `PLAYER_CENTER_X/Y` are only docs and test values. The reader takes the crop's centre and size, so a scaled minimap box already gives the scaled centre. Nothing to multiply there.

## What changed and why

- `MinimapReader` reads `profile.ui_scale`. The terrain shift is divided by it, so one tile is `ui_scale` px.
- The marker search radius is `max(2, round(2 * ui_scale))` px around the centre.
- Test: a synthetic radar moving 3 right and then 2 up, enlarged 1.5x with nearest-neighbour, tracks the same positions as at 1.0. With smooth enlarging, the 1 px synthetic marker greys out of the white tolerance, the same 1 px blur as in C3.F2.K1.
