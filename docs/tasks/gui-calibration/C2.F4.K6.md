# C2.F4.K6: Calibration summary, New and Delete

Part of [gui-calibration](../../prs/gui-calibration.md).

## Brief

Owner request, 2026-10-22:
- The Calibration tab always shows the picked calibration's last screen: the screenshot with its boxes.
- The user creates and deletes calibrations on the tab, instead of Save as at the end of a calibration.

**Done when:** pytest passes, with tests for deleting a profile and drawing the summary (tmp_path only). Owner checks: New, calibrate, Save, see the summary; switch calibrations and see each one's summary; Delete one.

## Router notes

2026-10-22:
- The screenshot is saved next to the profile as `<name>.png` on every save, including Esc's partial save. The summary is drawn from the profile's boxes on it, so it always matches the saved boxes. The PNGs are gitignored.
- New saves an empty calibration under the name and picks it, so it stays in the list until it is calibrated. A name that exists already is refused, since picking it from the list does that. (First version only picked the name, and the next New pushed it out of the list.)
- Delete asks first, removes the JSON and the PNG, and picks the first saved calibration left. With none left the name stays picked, and the next Save writes it.
- Save as is gone. The review keeps Save, which writes the picked calibration. Rule P1 is updated.

## What changed and why

- `ProfileManager.shot_path(name)` and `ProfileManager.delete(name)`.
- `summary_image(shot, profile)` draws the boxes and names on a copy of the screenshot.
- The idle view has New and Delete next to the dropdown, a line with the picked calibration's area count and UI scale, and the summary fitted to the tab. It refreshes on pick, New, Delete, Save and config changes.
- `_photo` is shared by the steps view and the summary.
